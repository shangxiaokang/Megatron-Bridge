# QwenAir vision integration plan

This document records the multimodal contract in the frozen Qwen4-Exp Hugging Face implementation and the smallest testable path from the current text-only Bridge. It is a plan, not a claim that `qwen4_exp` vision checkpoints or image/video training work today.

## Reference boundary

- Frozen oracle: `hf-qwen4-exp-oracle` at `2ff8a4b275`, especially `src/transformers/models/qwen4_exp/{configuration_qwen4_exp.py,modeling_qwen4_exp.py}` and `tests/models/qwen4_exp/test_modeling_qwen4_exp.py` in the QwenAir workspace.
- Target geometry: `model-info/p0/architecture.normalized.json` records 27 vision blocks, vision width 1152, 16 heads, a 2 × 16 × 16 patch, spatial merge size 2, and output width 2560. These are the target configuration values; the oracle class defaults are not the target checkpoint configuration.
- Existing text provider: `src/megatron/bridge/models/qwenair/qwenair_provider.py` accepts only `qwen4_exp_text`, one TP/PP/EP/ETP/CP rank, and no MTP training. Its checkpoint mapping describes logical text tensors, not the physical 128-shard PLE checkpoint layout.

## Input and computation contract

The top-level HF `Qwen4ExpForConditionalGeneration.forward` accepts `input_ids`, `attention_mask`, optional `position_ids`/`inputs_embeds`, `labels`, `pixel_values`, `pixel_values_videos`, `image_grid_thw`, `video_grid_thw`, and `mm_token_type_ids` (`modeling_qwen4_exp.py:2370-2410`). `Qwen4ExpModel.forward` implements the image/video merge (`modeling_qwen4_exp.py:2249-2324`). Its checkpoint has `model.visual.*`, `model.language_model.*`, and `lm_head.*` names; the standalone text checkpoint uses `model.*` and `lm_head.*`. A VLM mapping must route those prefixes explicitly rather than apply the text mapping unchanged.

The vision encoder consumes flattened preprocessed patches plus `grid_thw`, not raw image tensors. `Qwen4ExpVisionPatchEmbed` reshapes each row to `[in_channels, temporal_patch_size, patch_size, patch_size]` before Conv3d (`modeling_qwen4_exp.py:1685-1703`). The encoder adds interpolated learned 2D position embeddings and vision RoPE, processes variable-length patch groups through its blocks, and merges `spatial_merge_size²` patches per text token (`modeling_qwen4_exp.py:1849-1962`). The number of output tokens per item is `T*H*W/spatial_merge_size²` (`modeling_qwen4_exp.py:2140-2155`). Videos use the same feature path as images (`modeling_qwen4_exp.py:2128-2135`).

Before replacing placeholder embeddings, the HF wrapper preserves the original token IDs as `ple_input_ids`; PLE must continue to see those IDs, including modality placeholder IDs (`modeling_qwen4_exp.py:2269-2276, 2310-2317`). Image and video feature rows are concatenated in item order, checked against the respective placeholder counts, then inserted into the language input embeddings with `masked_scatter` (`modeling_qwen4_exp.py:2277-2297`; count validation at `2160-2196`). Mismatched counts must raise an error; the oracle tests this at `test_modeling_qwen4_exp.py:581-612`.

`mm_token_type_ids` uses 0 for text, 1 for image, and 2 for video. The oracle rejects image/video grids without this tensor when it needs to compute multimodal positions (`modeling_qwen4_exp.py:2198-2225`). Its M-RoPE groups consecutive modality types, expands each video's `T` grid into per-frame `[1,H,W]` grids because timestamps separate frames, and produces `[3,batch,sequence]` temporal/height/width positions (`modeling_qwen4_exp.py:2032-2123`). An explicit `position_ids` may bypass the position builder. The text model accepts three rotary axes and retains a separate text position axis when passed four axes (`modeling_qwen4_exp.py:1367-1416`).

The QwenAir MCore reference already computes interleaved M-RoPE from `[3,B,S]` or `[4,B,S]` positions in `megatron/core/models/qwenair/layers.py:85-109`. Its current `QwenAirTextModel.forward` always embeds `input_ids` itself (`megatron/core/models/qwenair/model.py:100-142`), so it cannot consume visually replaced embeddings. Extend it with an optional `inputs_embeds` path and an explicit `ple_input_ids` path while retaining the text-only call signature and shape checks. The multimodal wrapper should supply the original IDs for PLE, modified embeddings for the decoder, and computed three-axis positions. Tests must show gradients from the language loss reach the vision encoder through the feature scatter.

## Implementation sequence

1. Add MCore's embedded-input seam and compare its text-only result against the existing `input_ids` path with identical weights. Verify three-axis positions influence the QSA layers and preserve the original IDs at PLE layers. Keep independent QSA-indexer and MTP loss contracts explicitly unavailable.
2. Add a single-rank QwenAir vision encoder and wrapper that retain the HF patch, position interpolation, vision RoPE, attention, merger, scatter, and 3D position behavior. Bridge's `qwen_vl/qwen35_vl_bridge.py:68-145` contains candidate Qwen3.5 vision tensor mappings, and `qwen_vl/qwen35_vl_provider.py:597-627` builds a candidate Qwen3-VL vision encoder. Reuse only after strict tensor-key/shape coverage and same-weight output/gradient parity against the frozen oracle. The existing `Qwen3VLModel` discards `mm_token_type_ids` (`qwen_vl/modelling_qwen3_vl/model.py:600`), so its position path cannot be assumed equivalent to the oracle's modality-type grouping.
3. Add a separate `qwen4_exp` Bridge provider and `Qwen4ExpForConditionalGeneration` registration only after wrapper and conversion tests pass. Translate top-level `text_config` and `vision_config`, route `model.language_model.*` to QwenAir text parameters, map `model.visual.*` to vision parameters, and keep `lm_head.*`. Keep `qwen4_exp_text` as the standalone text registration.
4. Add the data path for processor-produced patches, grids, modality types, labels, and attention masks. Verify the same input batch and weights against the oracle before expanding parallelism or target-sized checkpoints. Validate the real 128-way PLE physical shard import separately; a logical state-dict roundtrip alone does not cover it.

## Minimum acceptance fixtures

- **One image:** tiny vision configuration with patch size 2, temporal patch size 2, spatial merge size 2, `grid_thw=[[1,2,2]]`, four flattened patches of width `3*2*2*2`, exactly one image placeholder, and `mm_token_type_ids` marking that position as 1. Compare vision output, 3D positions, logits, CE loss, and vision/text gradients to the frozen HF model with the same state dict. Test zero/multiple placeholders and wrong feature counts.
- **One video with two frames:** `video_grid_thw=[[2,2,2]]`, eight flattened patches, two video placeholders separated by a text/timestamp token, and type 2 on each placeholder. Compare the per-frame expanded positions, feature order, logits, CE loss, and gradients. Check that omitting `mm_token_type_ids` raises an error when video grids are supplied. The frozen oracle's smoke pattern converts image placeholders and inputs to video at `test_modeling_qwen4_exp.py:657-667`.
- **PLE and checkpoint:** enable a PLE layer in each tiny fixture and assert it receives the original placeholder IDs while the decoder receives substituted features. Require strict mapping coverage and HF-to-MCore-to-HF equality for all vision and text logical parameters; separately test real physical PLE shard import when implemented.
- **Training gate:** run a short image/video mixed optimizer step on B200/B300 and require finite forward loss, nonzero finite gradients for vision, merger, text, and PLE parameters, and HF parity at the selected tiny tolerances. This is a multimodal reference step only. Full QwenAir pretraining acceptance also requires the authoritative MTP and QSA-indexer training objectives, distributed PLE checkpoint import, and target-scale parallel execution.
